# 约定 —— 这个仓库把线画在哪里

**这份文档回答的是「为什么这么写」，不是「怎么写」。** 需要 API 形状看
[`API-CONTRACTS.md`](./API-CONTRACTS.md)，需要模块地图看
[`architecture.md`](./architecture.md)，需要已知边界看
[`limitations.md`](./limitations.md)。

它存在的理由是一次工程评审的结论（S8）：这个仓库中英混用，**模式其实非常清晰，
但从来没有成文**；没有成文的规则无法被复查，也无法在评审时被引用。

---

## 1. 语言：注释英文，面向用户/模型的串中文

这是仓库里**实际已经在执行**的规则，只是此前只存在于每个人的手感里。

| 位置 | 语言 | 理由 |
| --- | --- | --- |
| `src/**` 的 doc-comment / 行内注释 | **英文** | 代码是英文语法的；注释贴着代码读，切换语言会打断阅读 |
| `/** … */` 里的 `@param` / `@returns` / `@throws` | **英文** | 与 TS 生态的工具链一致 |
| 抛给用户看的错误串、门禁结论、面板文案 | **中文** | 这个插件的用户与队长是中文语境 |
| 喂给 LLM 的提示词片段（`src/prompt/**`） | **中文** | 提示词语言决定模型输出语言，与产物一致 |
| commit message | **中文** | 与历史提交保持一致 |
| 文档（`docs/**`、两份 README） | **中文** | 读者是人 |

**允许的例外**：为了说明而引用一段中文（例如注释里举例
`` `写着 4850，实际是 1601` `` 这种检查器输出格式），以及标识符本身是中文的场合。
引用不是混用 —— 规则针对的是**叙述语言**。

**怎么复查**（数字会动，所以这里不写死数字，只写怎么量）：

```powershell
# src/ 里含 CJK 的行数 / 文件数
node -e "const fs=require('fs'),p=require('path');let f=0,l=0,cl=0,tl=0;const w=d=>{for(const e of fs.readdirSync(d,{withFileTypes:true})){const q=p.join(d,e.name);if(e.isDirectory()){w(q);continue}if(!/\.tsx?$/.test(e.name))return;const s=fs.readFileSync(q,'utf8').split('\n');let h=0;for(const x of s){if(/[\u4e00-\u9fff]/.test(x)){l++;h++}if(/^\s*(\/\/|\/\*|\*)/.test(x)){tl++;if(/[\u4e00-\u9fff]/.test(x))cl++}}if(h)f++}};w('src');console.log('CJK 行',l,'/ 文件',f,'| 注释行',cl,'/',tl)

```

## 2. UI 文案只有一条生命周期 —— `src/client/locales.ts`

这是本节真正要立的规矩，也是 S8 指出的**真实风险**：

- `src/client/locales.ts` 是**唯一**的界面文案表，随 locale 切换。
- 服务端（`src/tools/**`、`src/domain/**`、`src/runtime/**`、`src/web/**`）**不得产出
  可直接展示给用户的界面文案**。

**为什么这条线必须存在**：服务端硬编码的中文串**不随 locale 切换**。一旦面板直接渲染
服务端串，界面就会中英混杂，而且没有任何检查会发现 —— `check-docs.mjs` 此前也不覆盖
两者的关系。这不是风格问题，是**两个互不相干的生命周期**被接在了一起。

**因此服务端返回的是可渲染的数据，不是句子**：

- 机器可判定的身份 → 结构化字段（`role`、`stage`、`gateType`、`code`、`path`、`round`…），
  由 `locales.ts` 选词渲染。
- 只有一句话能说清的人话 → 放进 `summary` / `verdict.notes` 这类**记录字段**，
  而不是塞进界面组件。记录字段是给队长和日志读的，不是给面板 `t()` 的。
- 未知值 → 报**未知**，不要发明一个有意义的默认值。`UNKNOWN_GATE_TYPE`
  （`src/shared/types.ts`）与 `UNKNOWN_ENDPOINT`（`src/client/api.ts`）是这条规则的样板：
  一个面板宁可显示「门禁未知」，也不该把 `'checklist'` 冒充成事实。

### 2.1 这条线已经被机器守住了一半 —— 而且不是靠新加的门禁

写这条规则时先查了一件事：**面板侧真的会漂吗？** 答案是**不会，而且是类型系统守的**：

- `zh`（`src/client/locales.ts:28`）是键集的唯一真源；
- `export type CodeFactoryLocaleKey = keyof typeof zh`（`:220`）；
- `export const en: Record<CodeFactoryLocaleKey, string>`（`:223`）—— 少一个键、多一个键，
  **都是编译错误**，所以两种语言不可能漂开；
- 组件拿到的 `t` 由框架按同一个键联合类型铸造（`:399` `TranslateFn`），所以
  `t('不存在的键')` **也是编译错误**。

**因此没有为"键集一致性"新加检查** —— 再加一个只会在类型检查已经报错之后才报错的脚本，
正是评审报告批评的那种"检查的检查"的表演。要守的是另一半：**服务端不要把界面文案当数据传给面板**。
这一半只能靠评审（即本节），因为"这句话该不该被本地化"不是语法属性。

**现状（实测，非断言）**：`src/web/**` 里唯一含 CJK 的字符串是
`src/web/routes.ts:343` 的 `console.warn` 文本 —— 它进的是宿主日志，不是面板；面板读的是
`snapshot.alerts` 里的结构化字段（`title` / `detail` / `next` / `severity`）。
`src/domain`、`src/runtime`、`src/tools`、`src/prompt` 里的中文串是 `summary` / `notes` /
错误消息这类**记录字段**，供队长与日志阅读，不经过 `t()`。这两类都是允许的。

## 3. 沉默必须是可解释的

`catch` 可以吞掉错误，但**必须能说出为什么**：

- 预期之中、且不携带信息的失败（可选宿主服务不存在、允许不存在的目录）→ 可以静默。
- 其余一切 → 至少留一次痕迹。样板是 `src/runtime/gates-runner.ts` 的读错误通道：
  `ENOENT` 静默（"不存在"与"读不到"在这里等价），其它 `code` 一律经 `onError` 上报，
  最终汇进 `GateRunResult.readErrors`，由门禁写进整改清单。

**反例（已修）**：该 catch 曾经**恰恰是唯一不上报的分支**，于是"文件存在但读不到"
被下游映射成 `工件不存在` —— 一个**事实错误**，而且没有任何诊断信息。

## 4. 数字要么有出处，要么不写

文档里的计数（模块行数、检查条数、角色数）由 `scripts/check-docs.mjs` 机器核对，
**没有一个计数是手工维护的**。写新数字前先问："这条数字由谁核对？" 如果答案是
"没有人"，就不要写它，改写成怎么复查。

**这条规矩同样约束这份文档** —— 所以上面第 1 节给的是命令，不是数字。

## 5. 一次改动的边界

- 一个提交只做一件事，提交信息说清**为什么**。
- 修复必须附带可复跑的证据（命令 + 退出码 + 输出）。"我改好了"不是证据。
- 检查要能红。新增的门禁必须在**注入缺陷的副本里真的失败过**一次，
  否则无法区分"检查通过"和"检查没在检查"。
