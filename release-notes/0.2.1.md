## 这个版本做了什么

自 `v0.2.0` 起的主线只有一件事：**把「只在文档里成立」的说法换成可执行的检查**。
按评审报告的九个维度记：

### 交付效率 / 运行稳定性

- 编制上限不再静默裁剪：模板所需人数超过上限时如实报告 `overCap`，不再悄悄降级。
- 跨进程写锁；写入持久化变成可验证的事实 —— `strategy` / `durability` 作为返回值
  带出来，`isDurableWrite()` 在 `src/store/store.ts` 里**被消费**，「原子路径降级为
  直接覆写」会以 `atomic-write-degraded` / `write-not-flushed` 浮出，不再静默。
- 收件箱写入有界；回滚从纸面流程变成 `backup:drill` 可执行流程。

### 功能完整性

- **`member.tokens` 过去永远是 0**：现在由该成员自己那份会话日志推导，继承来的
  前缀不计入；读不到时**保持原值而不是写 0**。`probeTokenSource` 把「没有这个服务」
  「服务在但形状不对」「可用」三种情况分开报告。
- 文档驱动的安全升级：PRD 正文（而不只是 brief）命中安全词时，门禁阶段把安全岗
  拉进编制并记录来源。

### 可维护性

- `src/tools/engine.ts` 拆分为 `src/tools/engine/` 下的 8 个模块，函数体逐字节未改，
  导出面严格等于原来的 16 个。
- 状态机收口：未知状态不再被静默接受。

### 恢复能力 / 工程规范

- `FACTORY_SCHEMA_VERSION` + 迁移钩子；`factory.json` 拒绝未知版本。
- CI 工作流、git hooks、`LICENSE`、`CHANGELOG.md`，以及 `v0.1.0` / `v0.2.0` 标签。
- `check:ci` 把 `release:check` 的命令链与 CI 工作流逐步互校。

### 测试有效性

- 三条离线演练：`drill:engine`、`drill:gates`、`drill:delivery`（最后一条真的把
  流水线走到 `phase: delivered`，并另起进程从 `factory.json` 读回判定）。
- `check:coverage`：把「从未执行」的 `src/` 模块收敛到一份逐条写明理由的白名单。
- `check:graph`：零环、零悬空 import，值依赖与类型依赖分开计数。
- `verify` 的新鲜度守卫：`lib/` 落后于 `src/` 时拒绝打分，而不是给陈旧对象发绿卡。

### 可观测性

- 告警成为可执行检查：`deriveAlerts` → `snapshot.alerts` → 面板 `AlertStrip`，
  `halted` / `rounds-exhausted` / `awaiting-approval` 都有消费者。
- 派发账本写进 `factory.json`；source map 随包发布。

### 发布溯源

- 打包门禁逐字节比对产物与检出，并以本文件记录 sha256。
