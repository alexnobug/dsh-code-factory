这个 sha256 由 `pnpm check:pack` 对**真实** `npm pack` 产物计算，并在每次运行时
与该文件比对：只要被发布的文件与检出出现任何字节差异，打包门禁就会变红。
上面「对应提交」不写死哈希是有意的 —— 标签 `v0.2.0` 就是那条链接，
写死哈希反而会在改写提交后变成一句谎话。

## 为什么 0.1.0 没有发布

仓库里曾经存在一个 `dsh-code-factory-0.1.0.tgz`，但它与同一版本号的工作树
**内容不同**（`lib/client.js` 一个 102677 字节、一个 111236 字节），
而且它比当时最新的两个提交**早约 3 天** —— 没有任何东西能指出它是从哪棵树上
打出来的。同时 `link:` 安装让「已安装」实际上是那个开发检出，而不是任何产物。
这个版本号因此被放弃，`0.2.0` 是第一个**产物、说明、提交三者可互相指认**的版本。

## 这个版本修了什么

发布链路（阻断级）：

- **B1** 全新 clone 打包产物为空：`prepack` 改为 `pnpm run build`，
  新增 `scripts/check-pack.mjs` 作为发布产物的硬门禁。
- **B6** 产物无法对应提交：发布说明 + 标签纳入机器校验（本文件）。
- **B5** 安装的是 `link:` 检出：README 与本文档改为从 tgz 安装验证；
  `link:` 仅用于开发。

安装自检（高风险 H9）：

- `doctor` 现在打印**被检的那棵树**（`repo:` / `mode:`），可用
  `--against <dir>` 指向真实安装，并在指错层级时拒绝运行。
- 新增一项检查：同一版本号下运行时加载的**是哪一个副本**。
- `scripts/doctor.mjs` 进入 `files[]` 与 `bin`，安装态因此可以自检。

元数据与兼容（中）：

- **M25** 补 `LICENSE`（`package.json` 早已声明 MIT，仓库里却没有）、
  `types/client.d.ts` 与 `exports["./client"].types`。
- **M26** 15 个 `@deepseek-ai/*` peer 由硬钉 `0.2.0-rc.2` 放宽为 `^0.2.0-rc.2`。
- **M4** README 的安装验证步骤由必然 `exit 1` 的 `--dump-config`
  改为 `dsh plugin --profile <name> ls`。

顺带修掉一个真 bug：`doctor` 的范围匹配器**无法解析带预发布标签的区间子句**，
`^0.2.0-rc.2` 会被整体判为不匹配，于是把正确的声明报成「不满足」。
现按 semver §11 实现，并在加载时用真值表自证，匹配器一失准就 `exit 2`。
